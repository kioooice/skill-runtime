# v0.2.0rc1

Date: 2026-05-06

## Release Summary

`v0.2.0rc1` is the first formal release candidate for the current maintainer-governance shape of Skill Runtime.

This release candidate is centered on one narrow but externally reproducible product claim:

- maintainers can capture a repeated workflow as an auditable record
- the runtime can surface an explicit governed follow-up recommendation
- the operator can inspect that recommendation without silent promotion or silent apply behavior
- provider quality, utility search quality, and workflow search quality now have fixed regression gates

## What Is Included

- the accepted maintainer-facing proof path based on `capture-trajectory --render-recommendation text`
- the checked-in v0.2 maintainer proof bundle and artifacts
- provider quality regression gating
- utility search quality regression gating
- workflow search quality regression gating
- explicit release-candidate checklist and version entry
- conservative governance boundaries around distill, promote, and apply

## Governance Boundaries

This release candidate keeps these governance boundaries explicit:

- no automatic `distill_trajectory`
- no automatic `promote_skill`
- no automatic `apply_evolution_candidate`
- no widening of `default-in`
- no active-skill wrapper added for governed learning follow-up
- no ranking changes made to convert expected workflow gaps into apparent passes

## Known Non-Blocking Gaps

- semantic audit is still mock-backed by default unless an external provider is configured
- fallback distillation is still mock-backed by default unless an external provider is configured
- retrieval remains lexical and local, not embedding-based
- Chinese retrieval remains explicit-alias-driven, not general multilingual understanding
- `maintainer_review_cleanup` remains a demo/proof-path workflow, not an approved active workflow-search skill
- governed learning follow-up remains a host follow-up operation, not an active workflow-search skill
- dashboard exists, but it is not the v0.2 release proof surface
- public traction remains limited and should not be overstated

## What Is Not Included

- no broader autonomous maintainer workflow automation claim
- no widening of runtime entry into broader task families
- no semantic retrieval claim
- no dashboard-first product claim
- no automatic promotion flow
- no automatic evolution-candidate apply flow
- no expansion of CLI recommendation scope beyond the accepted `capture-trajectory` path

## Default-In Boundary

No evidence from this release candidate supports widening `default-in`.

The current evidence proves:

- one governed maintainer proof path is real and reproducible
- provider quality can be regression-checked on a fixed fixture set
- utility search quality can be regression-checked on a fixed fixture set
- workflow search can distinguish real active matches from intentional expected gaps

It does not prove:

- broader runtime-entry safety
- broader workflow automation safety
- broader autonomous governed follow-up safety
- broader maintainer workflow coverage

Therefore this release candidate should not be used to justify widening `default-in`.
